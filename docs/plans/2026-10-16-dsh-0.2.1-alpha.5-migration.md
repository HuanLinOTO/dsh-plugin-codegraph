## 触点分析（源码 0 命中证据）

`rg -l "dsh-invariants|ctx\.invariants|\{\{cwd\}\}|webRuntime|projectUserText|FontSizeRow|ToolCallHookContext|TerminalBlockLabels|startContinuable|settleRun|run_in_background" packages` → **0 命中**（本仓在 0.1.2-rc.1 适配时已移除 `./invariant` 子路径与 `dsh-invariants` 依赖，见 CLAUDE.md）。

- `exec.agent?.session.header.cwd`（`packages/tool/src/index.ts` resolvedProjectRoot）：alpha.5 `packages/core/session/src/types.ts` 仍为 `header.cwd?: string`，typecheck 通过，**无需改**。
- `cordis.patch.yml`（bundle 层 4 行 insert）：行内无 config 键、无 `web-runtime`/invariants 行 → J1-03/J1-06 非命中。
- 5 包均 Host-only（无 client slot / settings / Remote / 协议 peer）→ J1-08/09/16 非命中。
- 本仓不自行 mount `dsh-tools`（只 peer 引用；宿主 bundle 自带 `dsh-working-directory`）→ J1-14 非命中。
- `@deepseek-ai/schemastery` 是普通 dependency（非 peer），`^3.18.4` 继续解析稳定版，host vendored `3.18.5-alpha.2` 仅是其自身运行时用 → 不动（J1-01 vendored-peer 规则只约束 peerDependencies）。

## 改动

1. **J1-01** — 4 个子包 peerDependencies 升级（devDependencies 不动，理由见"遗留"）：
   - `packages/service`：`dsh-brand`/`dsh-llm` → `^0.2.1-alpha.5`；`cordis` → `~4.0.5-alpha.2`
   - `packages/sqlite`：`dsh-llm`/`dsh-util-values` → `^0.2.1-alpha.5`；`cordis` → `~4.0.5-alpha.2`
   - `packages/tool`：`dsh-fs`/`dsh-llm`/`dsh-system-prompt`/`dsh-timeout`/`dsh-tools`/`dsh-util-values` → `^0.2.1-alpha.5`；`cordis` → `~4.0.5-alpha.2`
   - `packages/tree-sitter`：`cordis` → `~4.0.5-alpha.2`
   - bundle 无 `@deepseek-ai` peer，不动。
   - peer 下限从 `^0.2.0-rc.1` 提到 `^0.2.1-alpha.5` 意味着**不再支持 0.2.0 宿主**（prerelease 元组规则）。
2. **J1-02** — `pnpm-workspace.yaml` `minimumReleaseAgeExclude` 删除 `@deepseek-ai/dsh-invariants@0.1.7-rc.1`、`@0.2.0-rc.1` 两行（该包已在 alpha.5 消失，条目永不再匹配）；其余行服务于 devDeps 的 0.1.7/0.2.0-rc.1 cohort，保留。
3. **版本** — 5 包 `0.2.1` → `0.2.2`（沿 e3af62b 惯例：每次 dsh 适配一版）。
4. **README/README.zh** — fork notice「tracks the DSH `0.1.2-rc.1` line」→「tracks the `0.2.x` line (verified against `0.2.1-alpha.5`)」（历史适配一直漏更此行）。

无源码改动（typecheck 对 rc.1 与 alpha.5 双向干净）。

## 验证（junction 面向 dsh-v0.2.1-alpha.5 本地树）

> 本次禁跑 `pnpm install`（保持 lockfile/workspace 状态），devDeps 解析停在 0.2.0-rc.1 registry 拷贝。
> 为让 typecheck/test 真正打到 alpha.5，把 root + 4 子包 `node_modules/@deepseek-ai/*` 共 22 个链接
> junction 到本地 `dsh/` 树（tag `dsh-v0.2.1-alpha.5`，已全量构建，类型在 `lib/types/index.d.ts`）：
> `dsh-*` → `dsh/packages/**`，`cordis`/`schemastery` → `dsh/vendor/**`，`cordis-plugin-*` → `dsh/vendor/{loader,include}`。
> node_modules 不入库，junction 可随时被下一次 `pnpm install` 覆盖还原。

```powershell
# 基线（junction 前，0.2.0-rc.1 解析）
pnpm test               # 10 failed / 564 passed / 1 skipped
pnpm run typecheck      # exit 0

# junction 后（alpha.5 类型 + 运行时）
pnpm run typecheck      # exit 0（tsc -b --clean 后全量重建复核）
pnpm test               # 10 failed / 564 passed / 1 skipped —— 失败集与基线完全一致
pnpm run build          # exit 0（tsc -b，lib/ 为 .gitignore 产物，不入库）
```

typecheck 确实吃到 junction 类型：向 `@deepseek-ai/dsh-tools` import 一个不存在符号的探针文件
让 `tsc -b packages/tool` 报 TS2614 后删除，证明解析落在 `packages/tool/node_modules/@deepseek-ai/dsh-tools`（junction）。

CI（ubuntu，`pnpm install --frozen-lockfile`）：peer-only 编辑不动 lockfile 的合法性见 J1-01 field note
（autoInstallPeers 下显式 devDependencies 遮蔽同名自动安装 peer，lockfile specifier 仍与 package.json 一致）；
Windows-only 的 10 个失败在 ubuntu 上不出现（ci.yml 长期绿）。
